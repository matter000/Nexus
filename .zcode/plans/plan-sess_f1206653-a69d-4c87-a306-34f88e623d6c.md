# Harness Engine 设计方案

## 概述

将现有的 `tests/eval/harness.test.ts`（563 行，内嵌在测试文件中）提取为独立的 Harness Engine，支持 TOML 任务定义、Mock/真实两种运行模式、CLI + TUI 双入口。

---

## 文件结构

```
src/
  harness/
    Engine.ts          # 核心引擎：加载任务 → 运行 → 验证 → 报告
    TaskLoader.ts      # 从 .toml 文件或目录加载 EvalTask[]
    Validator.ts       # 验证规则引擎（文件内容匹配、文件存在、test 通过）
    Reporter.ts        # 生成报告（终端彩色输出 + JSON 导出）
    types.ts           # EvalTask, EvalResult, EvalReport 类型

tests/
  eval/
    harness.test.ts    # 保留，改为调用 Engine 的单元测试
    tasks/             # 示例任务目录
      math-rename.toml
      add-export.toml
      ...
```

## 核心设计

### 1. 任务定义格式（TOML）

每个任务一个 `.toml` 文件，放在 `tasks/` 目录下：

```toml
# tasks/math-rename.toml
[id]
name = "重命名函数"
category = "single-file"
difficulty = "easy"
description = "将 math.ts 中的 add 函数重命名为 sum"

[request]
user_prompt = "把 add 函数重命名为 sum，并更新所有引用处"

[[initial_files]]
path = "src/math.ts"
content = '''
export function add(a: number, b: number): number {
  return a + b
}
'''

[[initial_files]]
path = "src/main.ts"
content = '''
import { add } from './math'
console.log(add(1, 2))
'''

# 验证规则
[[validate]]
type = "file_contains"
path = "src/math.ts"
pattern = "function sum"

[[validate]]
type = "file_not_contains"
path = "src/math.ts"
pattern = "function add"

[[validate]]
type = "file_not_contains"
path = "src/main.ts"
pattern = "add("
```

**验证规则类型**：
| type | 参数 | 说明 |
|------|------|------|
| `file_exists` | path | 文件是否被创建 |
| `file_not_exists` | path | 文件是否被删除 |
| `file_contains` | path, pattern | 文件是否包含指定内容 |
| `file_not_contains` | path, pattern | 文件是否不包含指定内容 |
| `bash_pass` | command | 运行命令是否成功（exit 0） |
| `bash_output_contains` | command, pattern | 命令输出是否包含指定内容 |

### 2. 引擎核心（Engine.ts）

```ts
class HarnessEngine {
  constructor(opts: { 
    tasksDir: string,           // TOML 任务目录
    orchestratorFactory: () => Orchestrator,  // 工厂函数，注入真实/模拟 Orchestrator
    mode: 'mock' | 'real',
    parallel?: number,          // 并行运行任务数（默认 1）
    timeout?: number,           // 单个任务超时 ms（默认 300000）
  })

  async runAll(): Promise<EvalReport>
  async runOne(taskId: string): Promise<EvalResult>
}
```

**Mock 模式**：不调真实 LLM，用假的 Orchestrator（直接返回成功）验证框架和任务定义完整性。

**真实模式**：调用真实 Orchestrator.submit() 执行每个任务。

### 4. CLI 入口

```bash
# 跑所有任务（真实模式）
nexus eval ./tasks/

# 跑指定任务
nexus eval ./tasks/ --task math-rename

# Mock 模式（验证框架，不调 API）
nexus eval ./tasks/ --mock

# 指定模型
nexus eval ./tasks/ --model claude-sonnet-4-20250514

# 输出 JSON 报告
nexus eval ./tasks/ --json --output report.json
```

### 5. TUI 入口

`/eval` 命令：在 TUI 中交互式跑任务
- 列出所有可用任务
- ↑↓ 选择单个任务执行
- 实时显示任务结果
- 跑完显示汇总

1. `npx tsc --noEmit` — 零类型错误
2. `bun test` — 无回归
3. `nexus eval tests/eval/tasks/ --mock` — Mock 模式跑通
4. `nexus eval tests/eval/tasks/` — 真实模式跑通（需要 API Key）
5. `/eval` 在 TUI 中打开交互式选择器
