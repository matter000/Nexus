## 简介
本指南面向 Nexus 项目的开发者与质量保障人员，系统化阐述测试策略、框架选择、用例编写规范、工具 Mock 策略（特别是 MCP 工具与服务）、性能与压力测试方法、持续集成与自动化流程、覆盖率要求与质量门禁，并提供常见测试场景示例与最佳实践。目标是帮助团队在保持快速迭代的同时，确保代码质量、安全性与可维护性。

**更新** 随着 Agent 核心组件（Executor、Orchestrator、Planner）和检查点管理系统的完善，测试套件已扩展到超过500行新的测试逻辑，涵盖单元、集成和评估测试三个层面。

## 项目结构
Nexus 使用 Bun 作为运行时与测试执行器，测试脚本通过 package.json 的 scripts 暴露，统一由 bun test 驱动。测试目录按类型分层：
- tests/unit：单元测试，覆盖 CLI 参数解析、命令安全检测、上下文预算与压缩、成本追踪、通用工具函数、Agent 核心组件（Executor、Orchestrator、Planner）、Git 检查点管理、模型路由等。
- tests/integration：集成测试，围绕工具注册表与文件系统交互进行端到端验证，包括 CLI 参数覆盖和新工具功能。
- tests/eval：评估测试（Eval Harness），用于 SWE-bench 风格任务评估的骨架与占位用例。

## 核心组件
本节聚焦测试相关的核心能力与现有实现，包括测试运行配置、工具注册表、命令安全检测、Token 预算与压缩、成本追踪、Agent 核心组件以及通用工具函数。这些组件既是被测对象，也是构建高质量测试的基础设施。

- 测试运行与超时
  - 通过 bunfig.toml 设置测试默认超时，避免长耗时测试被误杀。
- 工具注册表与阶段过滤
  - 提供 createToolRegistry 工厂与 ToolRegistry 类，支持按阶段（plan/execute）过滤工具、生成 AI SDK 兼容定义、执行工具调用。
- 危险命令检测
  - CommandGuard 基于正则黑名单与启发式规则，返回危险等级并判断是否需要强制审批。
- Token 预算与历史压缩
  - TokenBudget 计算输入预算、分配各层预算、判断超预算与溢出量；Compressor 对长历史与工具结果进行压缩。
- 成本追踪
  - CostTracker 记录每次 LLM 调用的 token 数与估算成本，支持汇总、分组统计与重置。
- Agent 核心组件
  - **Executor**：执行阶段的 ReAct Loop，支持流式文本处理、工具调用、成本追踪和预算控制。
  - **Orchestrator**：编排核心，协调 Plan/Execute 双阶段、子 Agent 分派、检查点管理和外部 MCP 服务。
  - **Planner**：规划阶段的只读探索，生成结构化计划并调用 submit_plan 工具。
- Git 检查点管理
  - CheckpointManager 提供 Git 分支级别的检查点创建、回滚、合并等功能。
- 模型路由
  - ModelRouter 管理多 provider 初始化、模型降级、FALLBACK_CHAIN 完整性。
- 通用工具函数
  - Result 类型、截断策略（head/tail）、二进制输出清理、行尾处理与 BOM 去除。

### 工具测试的 Mock 策略（MCP 工具与服务）
- 原则：
  - 隔离外部依赖：对网络请求、文件系统、系统命令进行 Mock 或沙箱化。
  - 最小可行环境：使用临时目录与受控上下文（ToolContext）限定作用域。
  - 确定性输出：固定时间戳、随机种子与输入，保证可重复性。
- 具体实践：
  - 文件系统：使用 mkdtemp 与 tmpdir 创建隔离目录，afterAll 清理。
  - 工具注册表：通过 createToolRegistry 注入上下文，避免全局状态污染。
  - 命令执行：在 bash 工具中设置 bashTimeout，防止阻塞测试。
  - MCP 服务：若涉及远程服务，采用本地桩或服务虚拟化（例如 mock server）替代真实 API。
  - **AI SDK 模拟**：使用 mock.module 模拟 ai.streamText 和 generateText 函数。
  - **Provider 模拟**：模拟 @ai-sdk/anthropic 和 @ai-sdk/openai 的工厂函数。
- 推荐工具：
  - Bun 内置测试框架的 spyOn/mock 能力。
  - 自定义工厂函数替换依赖（如 createToolRegistry 已提供）。

## 故障排查指南
- 测试超时：
  - 调整 bunfig.toml 的 test.timeout，确认是否存在阻塞调用。
- 文件系统权限：
  - 检查临时目录创建与删除是否成功，确保 afterAll 清理。
  - **Windows 兼容性**：注意文件锁定问题，使用 force: true 选项。
- 工具执行失败：
  - 查看 ToolRegistry.execute 的错误返回，定位未知工具或参数错误。
- 危险命令误判：
  - 审查 CommandGuard 的正则模式，必要时添加白名单或细化规则。
- 成本统计异常：
  - 核对 CostTracker.record 的参数与价格系数，确认浮点精度。
- **Agent 组件问题**：
  - Executor：检查 streamText 的 usage 字段处理和成本记录逻辑。
  - Orchestrator：验证 init() 顺序和依赖注入是否正确。
  - Planner：确认 submit_plan 工具调用和消息历史管理。
- **Git 操作问题**：
  - CheckpointManager：检查 git 命令执行和分支切换逻辑。
  - 验证 git 用户配置和环境变量设置。
- **Provider 初始化问题**：
  - ModelRouter：确认 API Key 获取和 provider 可用性检查。
  - 检查 FALLBACK_CHAIN 的降级路径配置。
